# v0.10.1 セキュリティチェックの判定と確認手順

## 使い方

1. ダッシュボードでセキュリティチェックを有効にし、管理画面を開きます。初回表示で外部照会は開始しません。
2. 「再チェック」を一度押します。設定・記録・公式更新情報を読み、既知脆弱性の未照合製品を最大8製品ずつ自動で続行します。
3. 各行の現在の状態・判定理由と、個別の確認項目を見ます。「この項目の設定・確認方法を見る」で設定欄を開けます。
4. 必要に応じて対応する認証機能の設定や任意のCloudflare連携、観測の注意基準を設定します。認証機能や他のツールの設定をこの画面から変更することはありません。
5. 自動照合は一時停止・再開できます。画面を離れると続行を停止します。送信済みのPHP処理は完了する場合があります。JavaScriptが無効なら、残りがある時にネイティブの続行フォームを表示します。

## 状態表示と設定

リスクは低・中・高の横棒、未確認は灰色の棒と文字で表示します。個別の確認項目は「確認済み・要確認・要対応・要設定・取得失敗・計測/照合中・確認範囲外」に分けます。細い棒はこの内訳です。設定不足と測定できない範囲を一括で未確認にしません。

認証失敗の注意基準は初期値20件/分・5分の共有枠で10件です。設定の範囲は順に5～1,000件、5～60件。通信量は60～60,000件/分、5xxは1～1,000件、5xx率は1～50％で設定できます。この値は注意表示のみに使用します。共有枠の衝突や正常なアクセス増もあるため、攻撃成立とは断定しません。認証成功には2FA前のパスワード段階を含みます。

Cloudflareは任意です。対象ドメインの一致を確認した後、完了した24時間の通信量、管理WAFの有効な呼出設定、直近最大100件のイベントのactionだけを要求します。blockだけを遮断として数え、challengeやskipと区別します。IP・パス・クエリ・利用者エージェントは要求・保存しません。部分取得と失敗した統計を分け、0件に置き換えません。ゾーン限定のZone Read・Analytics Read・Zone WAF Readと契約プランで取得できる範囲を表示します。トークンはAES-256-GCMで暗号化し、フォーム・結果・ログに再表示しません。

サーバーの実行禁止・提供元PHPパッチの記録は管理者申告です。変更または「今回確認し直した」を選んだ場合のみ日時を更新し、7日で期限切れにします。観測基準の保存だけでは申告期限を延長しません。

## 続行処理と安全性

- manage_optionsと有効状態、POST、WordPress nonceを各要求で検証します。実行トークンは暗号学的乱数で管理者・サイト・製品一覧・設定に結び付け、完了後に破棄します。
- 再チェックは20秒間隔、続行は2秒以上の間隔で行います。所有者付きの排他制御を使い、最長10分・64処理・500製品で停止します。製品や設定の変更、期限切れ、別の実行は続行できません。
- 外部要求は固定HTTPS API・証明書検証有効・転送なし・Cookieなし。各要求最大3秒・1MiB、初回25秒/続行12秒の共通予算と35秒のブラウザ待機期限を維持します。DNSや進行中要求の終了は環境に依存します。
- 同じ実行で失敗製品を無限に再取得しません。新しい明示的な再チェックなら再試行し、成功した同じ版の結果は24時間再利用します。
- 製品キャッシュは最大500件・合計2MiB未満、各32KiB以下。容量に合わせて詳細を省略し、未確認として数えます。候補表示は製品20件・全体100件までですが、影響候補の総数と関連CWEの判定は維持します。
- 版条件は全ての境界を検証してから比較します。型・演算子・区間が不正なら該当なしとせず未確認にします。キャッシュの入れ子・出典URL・日時も検証します。
- 管理画面に出す事実・製品名・外部情報をエスケープします。不明な例外の内部メッセージは出さず、エラー時も排他を解放します。
- 認証フィルター、利用者の追加認証設定、WordPressの更新通知、既存のログや各ツールの設定は変更しません。攻撃、ログイン試行、アップロード、コード実行を使った診断は行いません。

## 検証

隔離MariaDBと公式WordPress 7.0/PHP 8.2、WordPress 6.0/PHP 7.4で確認します。各APIは成功・通信失敗・JSON不正・サイズ超過・転送・製品/ゾーン不一致・部分エラーを模擬します。WordfenceとTwo-Factorは公開メソッドのテスト用実装を使い、認証処理を実行しません。実際のCloudflare契約や実サイトの保護能力を試験したものではありません。

`tests/security-check-results.php` では5項目の正常判定、必要設定、失敗と待機、設定の検証、期限の不当延長防止、上限外CWE、500製品の保存容量、複数回のAJAX/ネイティブ続行、所有者・期限・回数・間隔・実際の製品変更による中断、例外の秘匿を確認します。既存のextended/multisite検証、Chromeの表示・自動続行・停止・再開・画面離脱・不正応答の確認、他機能の回帰検証も実施します。

配布対象ソースの差分と、本プラグインのSQL・XSS・CSRF・外部通信・ファイル参照を見直します。`audit.json` は配布時のレビュー対象PHP/JSと版・SHA-256の一致を確認するもので、未知の脆弱性や侵害がない証明ではありません。実行結果の件数はリリース説明に記載します。ZIP内の全ファイルと公開後に取得した資材を比較します。
