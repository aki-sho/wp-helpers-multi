## 利用者の設定

このプラグインを利用するサイトの管理者が、管理画面で接続先を選ぶ。開発者やCodexに契約情報・APIキーを渡す必要はない。コードの開発・試験で実サイト・契約サーバーのキーは使用していない。

### 試行制限

下部「各項目の設定・観測基準」で、許容回数の上限・計数期間の下限・停止時間の下限を変更できる。運用基準との比較であり、既存のログイン防御の値を変更しない。複数の適用済み設定のうち基準を満たす設定があれば、その確認範囲を採用する。回数等が未取得の場合は未確認を維持する。

### 独自配布の安全情報

「既知脆弱性の公開情報と照合する」と「独自配布元（GitHub）の公開済み安全情報も照合する」を選び、独自配布・MU・ドロップインの対象製品にリポジトリ（owner/repository）・パッケージ名・種類を指定する。WP Helpers Multiには `aki-sho/wp-helpers-multi` / `wp-helpers-multi` / `other` の初期対応がある。製品と配布元の対応は登録内容に基づく。

公開リポジトリは通常キー不要。非公開リポジトリは、そのリポジトリに対するRepository security advisories読取り権限を持つキーが必要。GitHubにはリポジトリ名を送り、インストール版の比較はサイト内で行う。未公開のアドバイザリや本文は要求しない。公開済みのアドバイザリがない場合は、その掲載情報内で該当なしという結果であり、未知の脆弱性がないことの証明ではない。

登録は20製品まで。1リポジトリ20件までで、20件に達した応答は続きが不明として未確認を維持する。比較は1〜2個の単純な版条件（`>= 1.0, < 2.0` 等）に限定し、ワイルドカード・OR・解釈できない条件を安全とは扱わない。キャッシュは製品・版・リポジトリ・パッケージの一致と24時間の期限を検証する。公開WordPress.org製品の照合元を、この登録で差し替えることはできない。

### サーバー・外部サービス

標準読取りは次の範囲。全ホスティングの非公開設定に一律対応したものではない。

| 取得方法 | 利用者が設定する内容 | 実際に読む内容・制約 |
|---|---|---|
| ローカルPHP | 追加接続不要 | PHP版・標準アップロード受信・最大実行時間 |
| cPanel | `account@panel.example.com` とAPIトークン | HTTPS 2083番の `ModSecurity/list_domains` のみ。対象サイトのドメインを照合し、ModSecurityの設定値を参考表示。PHP修正提供やアップロード先の実行禁止を推測しない |
| Cloudflare | Zone IDと読取りトークン | 既存のドメイン確認・通信統計・管理WAF・限定条件のログイン回数制限。各APIの失敗を別々に表示 |
| Fastly | Service IDとAPIキー | アクティブ版とドメインを確認し、約30分前までの完了した5分間の通信数・1分のピーク・5xx数を取得。サービスがこのサイトのドメインだけを持つ場合に限定。WAFやログイン制限を確認済みとはしない |

cPanelでは公開IPv4/IPv6を確認し、プライベート・予約・共有アドレス等を拒否する。cURLの接続IPを確認済みのアドレスへ固定し、TLS検証を維持する。cURLのHTTPS対応と直接接続が必要で、プロキシ経由は使用しない。標準ポートの例外とcURLフックは、そのURLの読取りの間だけ有効にし、必ず解除する。

追加サービスは既存の `wphm_security_readers` で登録できる。登録済みの読取り連携は、`WPHM_Security_Read_Exception('http_403')` 等の既知の理由コードを返せる。未登録・未対応のAPIや設定項目を、取得済みに見せる実装はしない。

サービス・接続IDを変更した場合、前の接続に保存されたキーを新しい接続先へ流用しない。新しい対象ではキーの再入力が必要。キーはWordPress内でAES-256-GCMにより暗号化し、選択した連携のAPIだけに使用する。HTMLのvalue・レポート・キャッシュ・例外文へ平文を出さず、開発者へ接続キーを送る処理はない。

### 利用者の分割確認

管理者を優先したあと、それ以外の利用者を1処理合計200人まで取得する。集計・処理位置は管理者・サイト別に保持し、利用者名・IP・パスワード・利用者IDの一覧を保存しない。完了した集計は5分、未完了の続行情報は最大24時間で期限切れにする。役割・関連する認証メタ情報・利用者構成の変更時は無効化する。独自の認証提供元の内部DB変更等は、次の再チェック・期限内の読取りの範囲で確認する。

自動続行は従来の所有者・nonce・権限・POST・2秒間隔・64処理・10分の上限を維持する。上限に達した未完了の利用者確認は、次の再チェックで有効な集計から再開する。最大100万人の防御的な上限を設け、到達時は完了・安全と扱わない。画面を離れるとブラウザの自動続行を停止する。

## プラグイン全体の再確認

- 全ツールの管理操作、CSV、設定、Ajaxの権限・nonce・状態変更メソッドを確認。
- SQL値のパラメータ化・固定テーブル名・並び替えの許可リスト、ID・型・件数の制限を確認。
- 管理画面、CSV、URL、レポート、JavaScriptへの受渡しの出力処理を確認。
- HTTP取得先、TLS、転送、応答サイズ、時間・件数上限、キーを送るホストを確認。
- 固定起点のファイル参照、シンボリックリンクの扱い、限定読取り、ユーザー入力による任意ファイル操作を提供していないことを確認。
- 既存ログの保持・秘密パラメータ保護、bcryptの方式・cost・72バイト制限、暗号学的な乱数によるパスワード生成、QRのローカル生成、検索置換の展開サイズ制限を確認。

全体点検で、配列・真偽値・数値の接頭辞が別のIDへ変換され得る処理を厳格化した。アクセスログの削除とコメント操作では正の整数だけを採用し、まとめ操作は200件まで。不正なAjax入力で既存ログが変化しないことを実際のエンドポイントで検証する。Wordfenceの回数・期間も整数として検証する。
