# v0.9.9 セキュリティチェック

## 操作と表示

WP Helpers Multiのダッシュボード「管理」に「セキュリティチェック」を追加しました。既存機能と同じ設定で有効・無効を切り替えます。有効時の専用メニューから開き、「再チェック」で設定・ログを読み直して公式の版・更新情報を照会します。JavaScript無効時もnonce付きPOSTで再チェックできます。

10項目を横棒で表示し、低＝緑、中＝黄土色、高＝赤、未確認＝灰色の斜線と文字で区別します。棒の長さは3段階を表すもので、点数や発生確率ではありません。既知の段階はアクセシブルなmeter、未確認は数値を持たない説明として表示します。確認日時はWordPressのサイトのタイムゾーンです。管理者の権限に依存する結果が混ざらないよう、結果キャッシュはサイト・管理者・プラグイン版ごとに5分間です。

## 判定条件

リスクは各行に書いた確認範囲の評価です。全攻撃経路の耐性や侵害の有無を証明するものではありません。ログに該当文字列がない、あるいは更新待ちがないだけで低とは判定しません。

| 項目 | 確認内容と判定 |
| --- | --- |
| ブルートフォース | 既存ログにログイン成否・試行制限の情報がないため未確認 |
| クレデンシャルスタッフィング | 漏えい・使い回し・全利用者の追加認証を確認できず未確認。パスワードの解析や照合は行わない |
| SQLインジェクション | SQL風の文字列を含む保存パスの件数を表示。クエリ/POST本文やSQLコードは監査していないため未確認 |
| XSS | 公開ユーザー登録が有効で、新規登録者の役割に未フィルターHTMLの編集権限がある単一サイトは高。その他はコード全体の入力/出力を監査しておらず未確認 |
| DDoS | ログの観測件数・記録内の1分最大・5xxを表示。記録省略とネットワーク側の情報不足があるため未確認 |
| CSRF | 全操作受付のnonce・権限検証を監査していないため未確認。WordPressにnonce APIがあるだけで低にはしない |
| RCE | 公式PHP情報で上流のセキュリティサポート対象外なら高。現在の管理者に管理画面からのコード編集が許可される場合は中。それ以外は未確認。独自パッチやRCEの成立は確認しない |
| ファイルアップロード | PHP標準のアップロード受信が無効なら、その経路に限り低。未検査アップロード設定が有効なら中。さらに公開登録者の役割が未検査アップロードを行える単一サイトなら高。その他の独自受付・保存後の実行可否は未確認 |
| 脆弱性悪用 | 公式コア版情報がinsecureなら高。未適用更新があれば更新面の注意として中。それ以外はCVE照合・コード監査をしていないため未確認 |
| ディレクトリトラバーサル | パス中の相対パス記号の件数を表示。実ファイル参照・コード全体を検証しておらず未確認 |

パス中のSQL/HTML風の文字列や `../` は、文字列の観測結果です。HTTP 200であっても攻撃が成立したと判定しません。マルチサイトでは新規登録者に単一サイトと同じ権限が付くと推測しません。

## 読取りの範囲と通信

- 既存アクセスログテーブルを読み取り、直近24時間の最新2,000件だけを集計します。2,001行目は上限検知に使います。テーブルがない場合も新規作成しません。ログ機能が無効なら残存記録だけを読み、無効であることを明示します。
- ログは時刻・HTTPステータス・パスだけを参照し、レポートには件数を保存します。URL・クエリ・IP・利用者ID・User-Agent・参照元・POST本文をレポートや外部通信へ含めません。元のログは変更しません。
- 通常表示では保存済みの更新情報を読みます。更新プロバイダーのフィルターを呼ばず、読取りをきっかけに別の更新処理が通信を開始することを防ぎます。版の不一致や24時間を超えるプラグイン/テーマの更新情報は未確認にします。
- 再チェックは `api.wordpress.org` の固定4 API（コア版の状態・PHPサポート・プラグイン更新・テーマ更新）だけを利用します。サイトへのHTTPアクセス、ログイン試行、ファイル送信、コード実行、パスワード検査、ポート走査、サイト巡回は行いません。
- WordPress.orgへの送信は版とプラグイン/テーマの識別名・名称・版等です。プラグインURI・テーマURIは送信しません。独自のUpdate URIを持つものは送信せず、公式APIに更新情報がないものは未確認です。サイトURL、認証Cookie、アクセスログ、ファイル内容は送信しません。
- 各要求は安全なWordPress HTTP APIを使い、HTTPS・タイムアウト3秒・転送追跡なし・応答1MiBまでとします。証明書検証は無効にしません。失敗・JSON不正・過大応答・転送応答は未確認にします。DNS解決等の時間は環境に依存します。
- WordPressの更新通知用transientを上書きせず、自動更新やインストール・修正を起動しません。独自の結果キャッシュと短時間の処理ロックだけを使用します。

## 権限と機能の分離

管理画面だけでモジュールを読み、無効時は読み込みません。画面・AJAX・POSTのすべてで機能設定と `manage_options` を確認し、再チェックではnonceも検証します。専用CSS/JSは対象画面だけで読み込みます。フロントの記録処理、ログイン処理、他機能の実装は変更しません。

再チェック失敗時は古い結果を最新と表示せず、エラーと前回の結果であることを表示します。APIだけが取得不能な場合は、現在の設定・ログの結果と、更新情報の未確認を表示します。文字列は画面出力前にエスケープします。

## 検証

新機能のWordPress検証127項目、フロント・無効時の分離6項目、Chromeによる画面検証37項目が通過しました。既存機能の回帰テスト708項目（共通116・検索置換84・セキュリティ改修75・投稿データ/URL一覧357・同画面59・QR等17）と、PHP/JavaScript構文68ファイルも通過しています。

`tests/security-check-wordpress.php` は隔離したWordPress/MariaDBと固定HTTP応答で、10項目の判定、危険な登録権限、未確認の保持、更新待ち、PHPサポート、TLS相当のエラー・不正/過大JSON・転送拒否、ログ件数の上限、データ非変更、管理者別キャッシュ、nonce・権限・機能無効時の拒否、並行処理、JavaScriptなしのPOSTを確認します。同スクリプトの `front` と `disabled` で、フロント・無効時にモジュールを読み込まないことも確認します。

`tests/security-check-browser.cjs` はWordPressが描画したHTMLと同梱JSをChromeで動かし、全10行・4状態・横棒とアクセシビリティ・確認日時・再チェック・エラー時の表示保持・再試行・スマートフォン表示を確認します。画面検証には架空の固定データを使い、実サイトの診断結果として扱いません。

公式4 APIの実応答形式も、Windows標準の証明書検証を使った公開サンプルで確認しました。プラグインからの統合テストは固定HTTP応答で実行し、実サイトへの攻撃は行っていません。
