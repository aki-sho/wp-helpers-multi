# v0.10.2 セキュリティチェックの取得元と画面改修

## 画面と操作

- 1〜10はネイティブの開閉式。閉じた状態では番号・項目名・横棒グラフを表示する。
- 開くと取得元ごとの状態と「確認項目」を表示する。各確認項目に設定・記録の場所を括弧で付記する。実設定が複数の場所にある場合は併記し、未取得は「確認先」と区別する。
- 「現在の状態」「判定理由」「確認範囲」の独立行と、確認状況の内訳を表す細い棒は廃止する。余白の変更はセキュリティチェック画面内だけに限定する。
- 上部のWordPress内・サーバー側・外部サービスは共通設定。選択は管理者・サイトごとに保持する。接続が必要な場所を選ぶと入力欄を開き、再チェックで検証・保存・取得を行う。選択や開閉だけでは外部通信しない。
- 公式更新・既知脆弱性の公開照合は、CDN/WAFの選択とは独立。公開照合には製品構成を使用し、WordPress.orgのPHP照合にはローカルPHP版を使用する。
- 再チェック後も開いていた項目を維持する。取得元・接続情報の変更時は自動続行を停止し、前回結果であることを示す。JavaScript無効時もPOSTによる再チェック・続行を利用できる。

## 1〜10の内容

| 項目 | 取得・判定と場所 |
|---|---|
| 1 ブルートフォース | WordPress内の認証処理を発見し、既存の制限の設定と標準ログインへの適用先を確認。サーバー・外部の読取り連携と合わせ、複数の制限を表示する。認証記録・集中は別の確認項目。 |
| 2 クレデンシャルスタッフィング | WordPress内の管理者の追加認証、HTTPS、アプリケーションパスワード、失敗後のパスワード段階の成功候補を確認。SSO等の未取得設定を無効と推測しない。 |
| 3 SQLインジェクション | 本プラグインの監査対象と配布ファイルの一致、関連する既知脆弱性の影響版を確認。外部の防御設定は参考扱いで、アプリ側の問題を打ち消さない。 |
| 4 XSS | 本プラグインの出力処理の監査一致と標準公開登録者のHTML権限を確認。外部ルールは参考扱い。 |
| 5 DDoS | WordPress到達通信・5xxと、選択したサーバー/外部の取得できた統計を別々に表示。基準期間が不足する比較から増加を推測しない。 |
| 6 CSRF | 本プラグインの操作受付・nonce・権限・メソッドの監査一致を確認。一般のWAF設定で代用しない。 |
| 7 RCE | WordPress内の実行コード権限、PHP上流の公開サポート情報、サーバー提供元の修正情報を分離。提供元情報で既知の問題を打ち消さない。 |
| 8 アップロード | WordPress標準の形式・サイズ・限定読取りと、選択したサーバー連携の実行禁止を分離。管理者メモや.htaccessの記述だけでは実効設定を確認済みとしない。 |
| 9 脆弱性悪用 | WordPress内の製品・版を選択した公開情報と照合。照合対象外・条件不明・失敗が残る場合は低にしない。既知の影響版や公式の危険判定は高を維持する。 |
| 10 トラバーサル | 本プラグインのファイル参照の監査一致を確認。外部の防御設定は参考として分離し、他製品全体への評価へ広げない。 |

棒は達成率ではない。判定に使う確認項目の要対応→高、要確認→中、不足→未確認、すべて確認済み→低の順で判定する。参考情報・未選択の調査で既知の問題を下げない。低は取得した対象だけの評価で、脆弱性が一切ないことや侵害されていないことを証明するものではない。

## 読取り連携

標準で、WordPress内の設定・認証コールバックのメタデータ、ローカルPHP版、Cloudflareを扱う。非公開のホスティング設定や他サービスは、提供元に対応する読取り連携が必要。任意のURL・パス・PHP名を管理画面に入力して実行する仕組みは設けない。

WordPress内は認証フック最大250件、表示最大60件。コールバックを診断目的で実行せず、Reflectionの配置情報からプラグイン・MU・テーマ・独自処理を発見する。絶対パスは表示しない。フック・製品名の存在だけで制限有効とは判定しない。標準の設定読取りはLimit Login Attempts / Reloaded・Wordfence、MFAはTwo-Factor・Wordfence Login Securityを利用する。その他は `wphm_security_auth_facts` の `limiters`、`wphm_security_mfa_facts`、または登録型の読取り連携で設定の根拠を返す。

登録型は信頼済みのインストールコードが `wphm_security_readers` フィルターで登録する。最大16連携、IDは40文字以内。`source` は `server` または `edge`、`name`、呼出可能な `read`、必要に応じて `needs_id`・`needs_token` を指定する。フォームからコールバックを指定できない。

`read` は `site`、`connection_id`、復号した `token`、`refresh` と、通信3秒・応答64KiB・20設定の上限を受け取る。連携実装も安全なHTTPS読取りAPI、固定/事前許可した接続先、転送拒否、時間・サイズ上限、対象サイトと権限の検証を実装する必要がある。インストール済みPHPをサンドボックス化する機能ではない。管理画面から自動的に連携PHPを作成・ダウンロード・実行しない。

戻り値は次の形式。記録やAPI応答全文、ユーザー名、IP等は返さない。

```php
[
    'schema' => 1,
    'site' => home_url('/'),
    'checked_at' => time(),
    'login_limits' => [[
        'enabled' => true, 'applied' => true,
        'tries' => 5, 'period' => 300, 'seconds' => 600,
        'routes' => ['wp_login'],
    ]],
    'capabilities' => ['uploads_execution' => true],
    'traffic' => ['requests' => 100, 'peak' => 10, 'errors' => 0, 'window_seconds' => 3600],
]
```

`applied` は対象サイト・明示した認証経路にその設定が組み込まれる根拠を確認できた場合だけtrueにする。単なる機能の存在は根拠にしない。`capabilities` は固定の8キーの真偽値/nullだけを採用し、`uploads_execution` のtrueは対象アップロード先でのスクリプト実行禁止を意味する。対象サイトが異なる応答・5分より古い応答・未来日時・型不正・過大件数は拒否する。未知のキーや文字列は保存しない。キャッシュはサーバー/外部で各1件、5分以内・接続署名一致・再検証を条件とする。今回失敗した読取りに、過去の成功を再利用しない。

Cloudflareは固定HTTPS APIへのGETとGraphQLの読取りだけを行う。ドメインを確認後、HTTP統計・管理WAF・`http_ratelimit` を別々に取得する。回数制限は最大100ルールから20設定まで。標準ログインのパス、任意のPOST・ホスト条件の単純なand式だけを確認し、or・not・追加の条件・異なる計数条件を推測しない。設定上の対象一致であり、プロキシ通過・例外・オリジン直アクセスを含む全経路の保証ではない。[Cloudflareの取得API](https://developers.cloudflare.com/api/resources/rulesets/subresources/phases/methods/get/)、[rate limitの公式仕様](https://developers.cloudflare.com/waf/rate-limiting-rules/create-api/)。

## 保護と検証

管理権限・機能の有効状態・POST・nonceを確認後に保存/取得する。キーはAES-256-GCMで暗号化し、HTMLのvalue、レポート、キャッシュ、例外には含めない。空欄で保持、明示的な削除に対応。接続IDのURL・パス形式、未知の連携ID、配列入力等は保存前に拒否する。不正入力で古いキーに黙ってフォールバックして成功扱いにはしない。

既存の上限付き集計、公式更新通知を変更しない照合、所有者・期限・回数制限付きの自動続行を維持する。認証試行・実ファイル送信・コード実行・防御設定変更は行わない。選択は調査の選択で、既存の防御・記録の有効/無効を変更しない。

検証は隔離MariaDB・公式WordPressのCLI統合環境とローカルブラウザ表示で実施する。外部API・提供元連携は成功・失敗・権限・別サイト・不正応答の固定データで検証する。実サイトや実際の契約の保護能力を攻撃して試験したものではない。
