# v0.9.7 サイト内URL一覧の改善

## 変更内容

### 収集前の除外設定

「アップロードディレクトリ配下のURLを除外する」を選択すると、WordPressが設定するアップロード先と、標準の `wp-content/uploads/` 以下を記録・巡回対象から外します。画像・ファイル・サブフォルダを含み、ディレクトリ自体も除外します。`uploads-old/` など別のディレクトリや添付ファイルの紹介ページは除外しません。URLのクエリ、パーセントエンコード、ドットセグメントを考慮してディレクトリ境界を照合します。

既定は除外なしで、選択した値は次回の収集にも保持します。実行中は設定を変更できません。一時停止中に選択を変えた場合も、再開時は開始時の設定を使用し、再収集時に新しい設定を適用します。除外対象はDBへの記録前に処理するため、発見件数にも含めません。

### ページ離脱時の削除

ページの `pagehide` で、現在の収集IDだけを指定した削除要求を `sendBeacon` で送ります。キューに入らない場合は `fetch` の `keepalive` を使います。収集URL・件数・収集状態を削除し、除外設定の選択は残します。同じページ内の検索・ソート・一時停止・CSVダウンロードでは削除しません。

収集バッチ中に離脱した場合は、10分間有効な削除要求を保存してバッチ終了時に削除します。他のリクエストが保存した要求を検知できるよう、オブジェクトキャッシュを再取得します。削除対象の収集IDが異なる場合は何も削除しないため、古いタブの離脱要求が新しい収集結果を消すことはありません。

戻る操作によるブラウザのページ復元でも古い一覧を表示しません。送信不能に備えて収集IDと時刻だけをブラウザに一時保存し、再訪問時に削除を再試行します。突然のブラウザ終了や通信断では即時のサーバー削除を保証できず、次回訪問時の再試行に依存します。

### アクセス権限

「確認状態」の右隣とCSVの末尾に同じ列を追加します。

| 表示 | 判断材料 |
| --- | --- |
| 未ログインでアクセス可 | Cookieやログイン情報を送らない取得でHTTP 200 |
| ログインが必要 | 標準管理画面のURL、またはWordPressのログインURLへの転送 |
| パスワードが必要 | HTTP 200の本文にWordPress標準のパスワード入力フォーム |
| 認証が必要（HTTP 401） | HTTP 401 |
| アクセス拒否（HTTP 403） | HTTP 403 |
| 未確認 | 未取得の静的ファイル、判断できない応答、取得失敗など |

管理者・編集者・投稿者などの役割別の権限は、URLだけから判断しません。独自の認証画面をHTTP 200で返すサイトでは、標準以外の制限を識別できない場合があります。`admin-ajax.php` と `admin-post.php` は未認証公開処理もあるため、パスだけでログイン必須とは判定しません。

### 全列の並び替え

URL・発見元・発見方法・HTTP・確認状態・アクセス権限の全6列にソートを追加しました。クリックのたびに昇順・降順を切り替え、方向を矢印と `aria-sort` で示します。HTTPは数値順、確認状態とアクセス権限は表示ラベル順です。ページの一部だけでなく、検索に一致する全結果をDBで並び替えてからページ分割します。CSVにも同じ条件を使います。並び替えの入力は許可リストで検証します。

## 検証

WordPressと隔離したMariaDBを用いた検証は144項目、Chromeによる画面検証は42項目を通過しました。

- `tests/site-data-wordpress.php`：スキーマ更新、ディレクトリ境界・エンコード・本文・転送先の除外、選択の保存と再開時の固定、権限判定、全列ソート、入力の許可リスト、nonce・管理者権限・機能無効化、収集IDに対応した削除、処理中の遅延削除、他リクエストの削除要求の再取得。
- `tests/site-data-browser.cjs`：項目表示、除外選択、実行中の設定固定、停止・再開・再収集、6列のクリックソート、CSVの条件、検索・CSVでの保持、ページ離脱時の削除、再訪問時の空の一覧、Beacon送信不可時の代替送信、狭い画面の横スクロール、実行時エラーなし。

ブラウザ検証では実際のWordPressが描画したHTMLと同梱JSを使用し、HTTP応答はローカルの固定データに差し替えています。WordPress側のHTTP取得も固定データを使用し、外部サイトに負荷をかけません。
