# セキュリティチェック 0.12.0

## 画面と判定

- 既存の20分類を維持し、165の確認行を「確認する対策・状態・確認先」に整理した。各分類は開閉できる。
- 状態は「設定あり・有効」「設定なし・無効」「未確認」の3種類。横棒は防御設定の状態別件数を示す。安全性の点数・攻撃への耐性・全項目の重要度を表すものではない。
- 記録・通知は防御設定の件数に含めず、別の開閉欄に表示する。旧リスク棒・管理者の申告メモは表示しない。
- 確認先の括弧表記は「（WordPress内）」「（サーバー側）」「（外部サービス）」のみ。取得根拠から場所を特定できた場合に表示する。公開HTTP応答だけでは設定元を特定しない。
- 「確認先を見る」で、取得した値、未確認の理由、次の操作、設定場所の例、検出位置を表示する。設定場所の例は利用サイトでその製品・設定が使われていることの証明ではない。
- コード・.htaccessの関連記述は候補として扱う。関数の呼出し、条件、対象経路、Webサーバーの実際の適用まで保証できないため、記述だけでは有効判定しない。

## 読取り対象

「WordPressの接続設定」は実行中のWordPressの設置先を自動表示する。パスは読取り専用で、フォームから読取り先を変更できない。FTP認証情報・APIキーは不要。

| 選択範囲 | 参照するもの | 対応範囲の制約 |
| --- | --- | --- |
| WordPressの設定 | DB・定数・標準権限・実行中のフィルター結果等 | 各行に明記した標準処理・利用者・経路の範囲。任意の独自認証の適用を保証しない |
| 設定ファイル・.htaccess | 設置先・公開先・アップロード先の.htaccess、通常のwp-config.php配置 | wp-config.phpの1階層上配置にもWordPressの条件に従って対応。他の上位階層や別サイトは走査しない |
| テーマ | 使用中の親テーマ・子テーマの実配置 | PHPを字句解析。解析対象コードを実行しない |
| プラグイン・MUプラグイン | 有効な通常・ネットワークプラグイン、MU、ドロップイン | 本プラグインは専用の配布時整合性照合に分離。任意の有効化条件を完全には解析しない |
| コード追加機能 | 有効なCode Snippetsの対応形式に保存されたPHP | 現在のサイトの既知のテーブルと対象scopeのみ。別製品・独自テーブル・ネットワーク共有の適用条件等は未確認 |

テーマ・コンテンツ・プラグインが設置先とは異なる場所にある場合も、WordPressが使用する配置を参照する。既知の実配置から指定されたルートを使い、子のシンボリックリンクや通常ファイル以外を除外する。サーバー全体を読み取る機能ではない。

「読取りを確認」は再チェックと同じ更新操作であり、現在選択している公開照合・外部連携も更新する。画面を開くだけでは新しいファイル走査を開始しない。

| 番号・分類 | 今回の整理・読取り | 確定しない範囲の例 |

| 7 RCE | コマンド実行関数の無効化数、ファイル編集禁止、RCE専用ルールを分離 | 一部関数の無効化や配布ファイルの一致はRCE耐性の保証ではない |
| 8 ファイルアップロード | 標準の許可形式・容量上限、形式検査や実行禁止設定の候補、対応APIの個別値を表示 | 独自アップロード、マルウェア検査、Webサーバーでの実適用は取得できる根拠に限定 |
| 9 脆弱性悪用 | 本体・製品・PHPの更新情報、既知脆弱性照合、本プラグインの配布時整合性を分離 | 未知の欠陥、情報未取得の製品、提供元独自修正を確認済みにしない |
| 10 ディレクトリトラバーサル | パス境界等のコード候補と専用ルールを分離 | コード候補だけでは任意のファイル参照経路の保護を確定しない |

| 12 セッション | 標準認証Cookieの属性・トークン処理、現在の管理者の保存済み有効期限を参照 | 独自Cookie・独自認証・全利用者のセッション設定 |
| 13 SSRF | WordPressの外部HTTP制限値、安全なHTTP API等のコード候補を表示 | 独自通信、ネットワーク送信制限、DNSの全経路の保護 |

| 20 CORS | 既存分類を維持し、公開トップの許可元・認証情報・Vary等を分離 | 認証後API・独自エンドポイントの全設定 |

## 外部連携と互換性

- 既存のCloudflare・cPanel・Fastly連携は任意選択で継続。未登録サービスを任意のURLやAPIキーで取得できるという表示はしない。
- PHP環境の参照は管理API接続とは分離。一般的なWAF有効値と攻撃種類ごとの個別ルールを同一視しない。
- API結果は選択した取得元のみを表示する。接続ID・認証キー・API応答原文は表示しない。
- 他のツールの動作・機能有効無効・既存の集計機能を維持。防御設定、ログイン回数制限、サーバー設定を新規に適用する機能は追加していない。

## 読取りの上限と安全措置

- ファイル走査は1処理最大100対象・約2秒、1処理の読取り約2MiB。1ファイル256KiB、合計1,000ファイル・保存コード／16MiB、最大10,000対象、深さ12、キュー2,000件、ディレクトリ直下512件、ルート250件、有効プラグイン200件。
- 保存スニペットはテーブルごと64件、合計2MiB。コード候補は60種類、各対策の位置情報は最大8件。上限・未対応・権限不足・対象なしを未確認理由として表示する。
- 分割処理は利用者・サイト・対象構成・版に結び付けて検証し、最長10分・64処理。対象変更・期限切れ・所有者不一致では古い処理を続行しない。
- 管理権限、POST、nonce、入力型を確認する。利用者からパス・SQL識別子・解析関数を指定できない。
- ファイルの実配置境界・リンク・通常ファイル・サイズ・オープン後の状態を確認する。コードはinclude/evalしない。コメントや単なる文字列を実行処理の証拠としない。
- 読み取ったコード本文・DB認証値・APIキーを解析キャッシュ、HTML、外部照会へ含めない。キャッシュは有限の検出種類、行番号、ファイル位置、件数等に限定する。表示は管理権限のある画面でエスケープする。
- 任意の独自コードや全サーバーの防御を自動判定できる機能ではない。「未確認」は対策なしと同義ではない。

## 配布

GitHubの0.12.0リリースと専用配布サーバーは別の公開先である。GitHub公開だけで `update.json` の既存配布先や導入済みWordPressが更新されることはない。サイトへの導入はWordPressでZIPを更新するか、専用配布先へ同じZIP・更新情報を配置して行う。
