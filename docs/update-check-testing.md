# 手動の更新確認（v0.9.3）

## 修正した問題

v0.9.1〜v0.9.2では、専用配布サーバーの更新情報を6時間キャッシュしていました。WordPress標準の「再確認」がこの独自キャッシュを無視しなかったため、サーバーに新しいZIPとJSONがあっても通知まで待つ必要がありました。

v0.9.3は、通常表示のキャッシュを維持しながら、明示的な更新確認ではサーバーへ問い合わせます。

- プラグイン一覧の「更新を確認」：更新権限とnonceを検証して再取得し、一覧へリダイレクトして結果を表示。
- 「ダッシュボード → 更新 → 再確認」：WordPress標準のforce-checkリクエストに対応して再取得。
- 対象はこのプラグインの更新情報のみ。他のプラグインのキャッシュやサイト設定は変更しません。
- 失敗時は以前の正常情報を表示できますが、確認に失敗した旨を区別して案内します。

## 回帰検証

2026-10-25、PHP 8.2.12で `php -n tests/maintenance.php` の116項目と `php -n tests/search-replace.php` の84項目が成功しました。前者は既存83項目に手動更新確認の33項目を追加しています。

追加した検証は、旧版の6時間キャッシュからの強制取得、通常表示では通信しないこと、標準の再確認フック、更新権限、nonce、HTTPの再取得指示、他プラグインのキャッシュ保持、ユーザーごとの結果表示、リダイレクト、取得失敗時のフォールバック、ネットワーク管理画面の戻り先を含みます。

この変更で実際の公開WordPressの設定・キャッシュは操作していません。編集画面内の検索・置換はv0.9.2から変更しておらず、その実画面検証は `editor-search-testing.md` に記録しています。

## 旧版から最初に導入する場合

旧版が実行中のままでは、この修正を使って旧版のキャッシュを無視することはできません。配布サーバーへ最新版を置いて期限切れ後に通常更新するか、WordPress標準のプラグインアップロードから一度上書き導入します。直接設定画面やセキュリティ設定の変更は不要です。
