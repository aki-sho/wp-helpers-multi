# v0.9.8 URLの種類ごとの除外・限定収集

## 操作

1. サイト内URL一覧の「収集するURLの種類」で「チェックした種類を除外」または「チェックした種類だけ収集」を選びます。
2. アップロードディレクトリ配下・画像ファイルへ自動転送するURL・添付ファイルページから、対象をチェックします。
3. 収集済みの一覧は自動で切り替わります。未収集の場合は「収集開始・再収集」で開始します。

設定用の保存ボタンはありません。収集中・一時停止中・完了後も変更でき、再収集を必要としません。収集中に変更すると、現在の通信が終わってから反映します。選択した値は次回も保持し、実際の適用内容を画面に表示します。保存失敗時はエラーを表示します。複数を選ぶ場合はOR条件です。種類を選ばない「除外」は全種類を表示し、「だけ収集」は空の一覧になります。

## 種類の判定

| 種類 | 判断材料 |
| --- | --- |
| アップロードディレクトリ配下 | WordPressのアップロード先と標準の `wp-content/uploads/` のパス。ディレクトリ境界・URLエンコード・ドットセグメントを考慮 |
| 画像ファイルへ自動転送するURL | 元URLが301/302/303/307/308を返し、転送先を検証した結果がHTTP 200/206かつ `Content-Type: image/*` |
| 添付ファイルページ | 数値の `attachment_id` パラメータ、またはWordPressで添付ファイルの投稿IDに解決されるパーマリンク |

添付ファイルページと画像への転送には重複があります。両方に一致するURLはどちらの選択でも対象となり、一覧では重複させません。固定ページ・投稿記事のURLは常に一覧から除外します。日本語名のURLについても、画像への転送を拡張子や名前だけで推定しません。

## 画像への転送確認

通常のHTML/XML/CSS/JSON等を取得する従来の処理に加え、画像・PDF・JavaScript等のファイルURLもHEADでヘッダーだけを確認します。ファイルの本文を巡回・実行しません。転送先もHEADで確認し、405/501の場合だけRange付きGETで再試行します。ヘッダー確認とその代替GETには最大512バイト、通常の本文取得には従来どおり1MiBの制限を設けます。

転送先を自動追跡するHTTPクライアント設定は使わず、各URLを同一サイト・公開IP・HTTP/HTTPS・80/443ポート等の条件で検証します。転送先の追跡は最大5段で、HEAD非対応時の再試行も全体2,000回の通信上限に含めます。1バッチは最大3回の処理・約9秒、各HTTP要求は3秒です。DNS解決の待ち時間はOSに依存します。

管理・ログイン・実行用URLや一般のクエリ付きURLは自動取得しません。数値の `attachment_id` だけを持つ参照用クエリを例外とし、他のパラメータが混ざる場合は取得しません。外部サイトへの転送、内部IP、取得失敗、転送ループ、上限到達などは画像と断定しません。

「画像ファイルへ自動転送するURL」の選択時は、判定待ち・判定不能のURLを画像転送について保留します。「除外」では画像でないことを確認したURLを残し、「だけ収集」では画像への転送を確認したURLだけを含めます。アップロード先や添付ページも一緒に選んだ「だけ収集」では、その既知の種類に一致するURLも含めます。画面に確認待ちと判定不能の件数を表示します。

## 一覧・CSV・保存

チェック変更で結果を復元できるよう、表示対象外の候補もページ離脱まで一時保持します。「だけ収集」でもURLを見つけるために対象外のページを巡回します。10,000URLの上限は非表示も含めた候補全体に適用します。検索・全6列の並び替え・ページ分割・CSVは同じ種類の条件を使用します。CSV開始時に条件を固定し、出力途中の設定変更でページごとの条件が混ざることを防ぎます。

ページ離脱時は非表示も含めた全候補と収集状態を削除し、種類の設定は保持します。収集IDを照合して削除する既存の保護も継続します。v0.9.7のアップロード除外設定は引き継ぎます。スキーマ1.2.0への更新では既存結果を消さず、旧結果の種類を最大20行ずつ自動で分類し、旧転送URLも再確認します。

## 検証の範囲

WordPress/MariaDBの357項目、Chromeの59項目、共通処理・検索置換の回帰テスト200項目を通過しました。PHP/JavaScriptの構文確認は63ファイルです。

`tests/site-data-wordpress.php` は隔離したWordPressとMariaDBを使い、3種類×除外/限定の全16通りの選択、即時切り替え、収集ID・候補の保持、添付ID/パーマリンク、ディレクトリ境界、ソート、スキーマ更新、実行中の設定保存、nonce・管理者権限・入力検証、離脱時の削除を確認します。

HTTP応答は固定データに差し替え、「スクリーンショット-451/ → uploads内のPNG」の形、複数回の転送、拡張子なし画像、PNG名でHTMLを返す応答、HEAD非対応、通信失敗、転送ループ、内部IPへの転送、静的ファイルURLの転送を検証します。実サイト全体を巡回して検証したものではありません。

`tests/site-data-browser.cjs` は実際のWordPressが描画したHTMLと同梱JSをChromeで動作させ、3種類それぞれの除外/限定、チェックのみでの保存・復元、収集中の変更、連続変更の最終値、停止・再開、CSV操作、検索・ソート、ページ離脱時の削除、実行時エラーの有無を確認します。画面側のHTTP応答はローカルの固定データを使用します。
